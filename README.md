# 评测小工具（eval-mini）

给分类系统做最小可用评测：固定评测集、写死的判定规则、可复算的人机一致率。

## 要解决什么问题

“这版系统比上一版好多少”，如果只靠人肉抽几条看看，结论没法复现，也没法说服人。同一批数据，换个人看、换个时间看，结论就变了。

这个仓库把评测拆成三件可量化的事：一份固定的评测集、一套写死的判定规则、一个能算出来的人机一致率。同一批数据，任何人跑都得到同一个分数。

## 怎么装

需要 Python 3.12。

```bash
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 怎么跑

四条命令，按顺序：

```bash
.\.venv\Scripts\python.exe src\make_cases.py   # 生成 200 条评测集
.\.venv\Scripts\python.exe src\predict.py      # 跑被测系统，产出预测
.\.venv\Scripts\python.exe src\judge.py        # 判四档，按层汇总
.\.venv\Scripts\python.exe src\agreement.py    # 人工 vs 机器，算一致率
```

## 跑完长什么样

```text
分层汇总（通过率 = 完全正确 / 该层条数）
判定    完全正确  部分正确  错误  未作答  合计    通过率
分层
正常      90     0   0    0  90  100.0
边界      50     0   0    0  50  100.0
对抗      35     0   0    0  35  100.0
历史失败     8     0  17    0  25   32.0

总体：200 条，完全正确 183 条，通过率 91.5%

抽检 40 条，一致 22 条，人机一致率 55.0%
```

总体 91.5%，历史失败层 32%。这个落差就是这套工具存在的理由——只看总体分，看不出问题在哪一层。

完整分析见 [report.md](report.md)，判定口径见 [rules.md](rules.md)。

## 数据从哪来

`data/cases.csv` 由脚本生成，200 条分四层：正常 90、边界 50、对抗 35、历史失败 25。每条含现场描述、标准答案、分层、可接受的其它答案。

`data/human_40.csv` 是人工抽检表，每层 10 条，由人独立标注，用来算人机一致率。这一列必须人填，脚本代劳就失去意义了。

被测对象是 `src/predict.py`，一个关键词分类器，代表上一版系统。判定器和生成器都不依赖它——把 `data/pred.csv` 换成大模型的输出，判定逻辑一行不用改。
